# Day 8 — Persist User Onboarding Data

## Date

August 23, 2026

## What I Worked On

Today I implemented persistent data storage for Ping using Jetpack DataStore Preferences as part of Issue #7.

I created a `UserPreferencesRepository` to manage user data, implemented the logic to save the user's name and onboarding completion status, and updated the Splash Screen to handle returning users.

Now Ping remembers the user after the app is closed and reopened, allowing returning users to skip onboarding and go directly to the Home Screen.

## What I Learned

Today I learned how Jetpack DataStore Preferences can be used to persist small pieces of local application data.

I also learned how the Repository pattern can separate data access from the UI, how `Flow` is used to read reactive data from DataStore, and how Kotlin Coroutines allow

suspend operations such as DataStore writes to be performed without blocking the UI.

I also learned how `.first()` can be used to get the current value from a `Flow` when making an immediate navigation decision.

## Challenges

The main challenge was connecting the existing onboarding and navigation flow with persistent data without breaking the current user experience.

I also had to understand how the saved onboarding state and saved name should be read during Splash so Ping could distinguish between a new user and a returning user.

## Result

Issue #7 is complete.

Ping can now remember the user across app restarts and correctly determine whether to show onboarding or take the user directly to Home.

The flow is now:

### New User

```text
Splash Screen
↓
Onboarding
↓
Welcome
↓
Let's Begin
↓
Save User Data
↓
Home
```

### Returning User

```text
Splash Screen
↓
Read Saved User Data
↓
Home
```
